# Demo video script

Under three minutes, eight beats, one fresh demo copy. Each beat names the screen to show, what to click, and one line to say. The times are a budget, not a stopwatch.

## Before recording

- Open the hosted demo once a few minutes ahead, so Render is awake, and check the pool has a deposit ready (`npm run demo:pool -- --status`).
- Enter the judges' code in a private window: a fresh copy, dated today. Use Start over if you rehearsed in it.
- Two windows side by side: the landlord on the left, the tenants' page on the right. "Open the tenant's view" opens a new tab, not a window, so drag that tab out to the right once it opens.
- Beats 5 and 7 hold six clicks each in 25 seconds, which fits only without fumbling. To give beat 5 room, record the statement's delivery off camera right after beat 4 (Statement, Record delivery, any method), open the tenant's view then and drag it into the right window, and start beat 5 on the tenants' page. Rehearse 5 to 7 once on a spare copy (Start over gives a fresh one).
- Three waits are real Claude or PayPal calls: the lease check (about 20 seconds), the close-out agent (under a minute) and the advocate (about a minute). Record them and cut the wait. Run the lease check once before recording if you want its result on screen without the wait.
- If the negotiation runs long or the agents don't agree on camera, beat 6 can use 482 N. Glassell St, Unit B instead, which comes with a settled dispute. Say it is the demo's recorded example. Its beat 7 shows the settlement row and the amended statement, but no PayPal refund id: no PayPal money moved for it, and the page says "Demo example". The PayPal refund then rests on beat 4, so prefer a re-take of the live run for the final cut.

**Optional beat 7b, chargeback defense (about 25 seconds, for a longer cut).** Set up off camera on a second fresh copy (Start over): its move-out unit has its own pre-paid sandbox deposit. First send its refund as in beat 4 ($3,790 back; the statement keeps $1,010). Then, as the sandbox tenant, open that refund in the PayPal sandbox's Activity and follow View receipt to the deposit payment (Show invoice details gives its invoice number, which the property's Payments tab shows too). Choose Report a problem, then "I want a refund for some or all of the items in this order", item type Service and category Other, "The seller agreed to issue a refund", $1,010.00, No for contacting the seller, one sentence (the charges are normal wear), and Submit. PayPal reviews it for a few minutes before it opens the dispute to the landlord. File once per payment: a second report on it is merged into the first and can send it back to PayPal's review, and "my account is being used by someone else" makes the sandbox account ask to be secured. The deposit is used afterwards, so `npm run demo:pool -- --fill` once you're done. On camera: the unit's red PayPal dispute chip on Properties, then its Payments tab: Check PayPal, Prepare a response (a Claude call, under a minute; cut the wait). Nothing is owed back by the rules, so evidence is allowed, and the agent sends it: the itemized statement's PDF, each charge's move-in and move-out photos with the box drawn, the invoices, and proof of the $3,790 refund. Then Approve and send. Say: "If the tenants go to PayPal instead, the defense agent answers from the same records: the statement, the boxed photos, the refund. Code won't let it argue for keeping a dollar the law says goes back, and nothing reaches PayPal until I approve it." (On a copy whose refund hasn't gone, the only lawful answer is to give the money back through the dispute: that is the case the README describes, not the one to film.)

Close on the Properties page (2:55 to 3:00): "Good Faith. AI that informs and negotiates inside the law, PayPal that pays only when both sides say yes. Not legal advice."

## What each beat proves

- Beats 1 to 3: Claude reads and classifies; code decides every amount (`rules.ts`, `deductions.ts`).
- Beat 4: agentic commerce with a human approval on every money tool (`agent.ts`, `needsApproval`, `guardRefund`).
- Beats 5 to 7: two agents for two humans, bounded by code (`lawful-range.ts`, `negotiator.ts`), settled through PayPal only after both approve (`settlement.ts`).
- Beat 8: the state packs (`src/lib/states/`, `docs/rules/`).
- Beat 3b: AG Grid and AG Charts Community, the deductions edited in place against the lawful range, and the portfolio in one ledger (`deductions-grid.tsx`, `deduction-edit.ts`, `insights.ts`).
- Beat 3c: Jev's typed judgments beside Claude's reasoning, held by code (`jev.ts`; the same model checks the agents' reasons in beats 5 to 7).
- Beat 7b: a PayPal dispute read through the Agent Toolkit, answered by an agent bounded by the lawful range, sent only on approval (`chargeback.ts`, `chargeback-agent.ts`, `chargeback-store.ts`).
